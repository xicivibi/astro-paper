매달 내려받은 CSV를 한 표로 합칠 때는 파일을 붙이는 것보다 **어떤 파일의 어떤 행이 들어왔는지 검증하는 일**이 더 중요합니다. 제목 행이 데이터로 한 번 더 들어가거나, 파일마다 열 순서가 달라 값이 엉뚱한 열에 놓이면 합계는 계산되더라도 결과가 틀릴 수 있습니다.

Power Query의 폴더 결합은 같은 구조의 파일을 반복해서 모으는 데 적합합니다. Microsoft도 전용 폴더에 결합 대상 파일만 두고, 파일들이 일관된 스키마를 갖도록 준비하라고 안내합니다. 열 순서가 달라도 열 이름이 일관되면 이름을 기준으로 맞출 수 있습니다.

## 결합 전에 전용 폴더부터 만듭니다

운영 폴더에는 실제 결합 대상만 둡니다.

```text
monthly-orders/
├─ january.csv
├─ february.csv
└─ march.csv
```

임시 복사본, 설명용 CSV, 이전 양식 파일이 같은 폴더에 있으면 폴더 쿼리가 함께 읽을 수 있습니다. 별도 보관 폴더로 옮기고 다음 항목을 먼저 확인합니다.

- 각 파일의 첫 행이 같은 의미의 열 이름인지 확인합니다.
- `order_id`, `amount`처럼 필요한 열의 이름을 고정합니다.
- 코드 열은 텍스트, 금액 열은 정수처럼 기대 자료형을 정합니다.
- 파일별 출처를 확인할 수 있도록 `Source.Name` 열을 남깁니다.

## Excel에서 폴더를 결합하는 순서

Excel 버전에 따라 메뉴 표현은 조금 다를 수 있습니다.

1. **데이터 → 데이터 가져오기 → 파일에서 → 폴더에서**를 선택합니다.
2. 결합 전용 폴더를 지정합니다.
3. 파일 목록에서 예상한 파일만 보이는지 확인합니다.
4. **결합 및 변환 데이터**를 선택합니다.
5. 샘플 파일 변환에서 제목 행을 한 번만 머리글로 올립니다.
6. 최종 쿼리에서 `Source.Name`, `order_id`, `amount`를 확인합니다.
7. `order_id`는 텍스트, `amount`는 정수로 지정합니다.
8. 행 수, 파일별 행 수와 합계를 확인한 뒤 로드합니다.

`Source.Name`은 검증이 끝날 때까지 지우지 않는 편이 좋습니다. 합계가 맞지 않을 때 어느 월 파일에서 누락이나 중복이 생겼는지 바로 좁힐 수 있습니다.

## 헤더가 데이터로 들어가는지 확인합니다

두 파일을 결합했는데 결과에 아래와 같은 행이 있으면 제목 행 처리 단계를 살펴봐야 합니다.

```text
order_id | amount
order_id | amount
A001     | 100
```

각 파일의 제목 행을 데이터로 남긴 뒤 전체 결과에서 다시 머리글을 올리면 제목 문자열이 일반 행처럼 들어갈 수 있습니다. 샘플 파일 변환에서 머리글 승격이 한 번 적용되는지 확인하고, 최종 결과에는 `order_id`나 `amount`라는 값이 데이터 행으로 남아 있지 않은지 검사합니다.

## 열 위치 대신 열 이름을 확인합니다

아래 두 파일은 열 순서가 다릅니다.

```csv
order_id,amount
A001,100
```

```csv
amount,order_id
300,B001
```

두 번째 파일의 첫 번째 값을 무조건 `order_id`로 취급하면 `300`이 주문 코드 열로 들어갑니다. 폴더 결합에서는 모든 파일의 열 이름과 의미를 같게 유지하고, 결과가 이름 기준으로 정렬됐는지 확인합니다. 열 이름이 바뀐 파일이나 열이 빠진 파일은 정상 파일과 섞기 전에 별도로 처리해야 합니다.

## 실제 재현 결과

2026년 9월 13일 Windows의 Excel 16.0 빌드 20326, `ko-KR` 환경에서 고정된 합성 CSV로 재현했습니다.

첫 시험에서는 `january.csv`와 `february.csv`를 결합했습니다.

| 확인 항목 | 결과 |
|---|---:|
| 전체 데이터 행 | 4 |
| january.csv | 2 |
| february.csv | 2 |
| amount 합계 | 1,000 |
| order_id 자료형 | 텍스트 |
| amount 자료형 | 정수 |
| 제목 행의 데이터 혼입 | 없음 |

결과 행은 `A001=100`, `A002=200`, `B001=300`, `B002=400`이었습니다.

두 번째 시험에서는 열 순서가 다른 `march.csv`까지 **첫 로드 전에** 폴더에 둔 상태로 같은 쿼리를 실행했습니다. 첫 로드와 같은 QueryTable의 두 번째 새로고침에서 모두 6행, 합계 2,100, 파일별 2행이 확인됐습니다.

이 시험은 새로고침 도중 파일을 추가하거나 삭제한 동작을 검증한 것이 아닙니다. 세 파일이 처음부터 존재하는 조건에서 같은 쿼리의 반복 새로고침 결과를 확인한 것입니다. 실제 운영에서 파일 추가·삭제를 자동 반영하려면 별도의 변경 시험을 거쳐야 합니다.

## 새로고침 후 확인할 값

새 파일을 넣고 **모두 새로 고침**을 실행한 뒤 다음 값을 함께 비교합니다.

- 폴더의 대상 파일 수
- `Source.Name`별 행 수
- 전체 행 수
- 금액 합계
- 코드 열과 금액 열의 자료형
- 제목 행이 데이터로 남았는지 여부

행 수만 맞아도 안심할 수 없습니다. 한 파일의 두 행이 빠지고 다른 파일의 두 행이 중복되면 전체 행 수는 같을 수 있습니다. 파일별 행 수와 합계를 함께 확인해야 합니다.

## 이 글의 확인 범위

이 글의 실행 결과는 Windows, `ko-KR`, Excel 16.0 빌드 20326과 해시가 고정된 합성 CSV에 한정됩니다.

- 두 파일 결합 재현 artifact: `5f79db79f6196736bee7991daf80e964364940121076e108172eb74c3db1fcbb`
- 세 파일·같은 QueryTable 새로고침 재현 artifact: `ae3536b36843c5b0bad4b8bee9cd565a02d5f974fe021325c5694632fb8f7e92`
- 재현 날짜: 2026년 9월 13일

행의 원시 출력 순서, 첫 로드 뒤 파일의 동적 추가·삭제, 다른 Excel 빌드와 운영체제의 결과는 이 재현으로 보장하지 않습니다.

## 저장 전 체크리스트

- [ ] 결합 대상만 있는 전용 폴더를 사용했습니다.
- [ ] 모든 파일의 열 이름과 의미를 확인했습니다.
- [ ] `Source.Name`을 남겨 파일별 행 수를 확인했습니다.
- [ ] 제목 행이 일반 데이터에 섞이지 않았습니다.
- [ ] 코드 열은 텍스트, 금액 열은 기대한 숫자 형식입니다.
- [ ] 전체 행 수와 파일별 행 수가 모두 맞습니다.
- [ ] 새로고침 전후 합계가 기대값과 일치합니다.
- [ ] 새 파일 추가·삭제 동작은 별도 조건으로 시험했습니다.
