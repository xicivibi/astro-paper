Power Query의 **중복 제거**를 바로 누르면 행 수는 줄어듭니다. 하지만 무엇을 같은 값으로 볼지 먼저 정하지 않으면 필요한 행도 함께 사라질 수 있습니다.

아래 값은 사람에게는 같은 코드처럼 보일 수 있지만 원시 텍스트는 다릅니다.

```text
A
a
 A 
빈 값
```

Power Query의 중복 비교는 대소문자를 구분합니다. 선택한 열을 기준으로 중복을 제거할 수 있고, 어떤 중복 행이 남을지는 보장되지 않습니다. 따라서 제거 전에 **비교 키**, **정규화 규칙**, **남길 행의 기준**을 먼저 문서화해야 합니다.

## 먼저 중복의 종류를 구분합니다

같은 파일에도 서로 다른 중복이 섞여 있을 수 있습니다.

1. **완전히 같은 행**: 모든 열의 값이 같습니다.
2. **키만 같은 행**: 고객 코드나 주문 번호는 같지만 날짜·상태·금액이 다릅니다.
3. **표기만 다른 키**: `A`, `a`, ` A `처럼 대소문자나 공백이 다릅니다.
4. **빈 키**: 빈 문자열이나 null이 여러 행에 있습니다.

모든 열을 선택한 중복 제거와 특정 키 열만 선택한 중복 제거는 결과가 다릅니다. 주문 번호만 같고 상태가 다른 두 행을 전체 열로 비교하면 둘 다 남지만, 주문 번호만 비교하면 하나가 제거될 수 있습니다.

## 안전한 작업 순서

원본 쿼리를 직접 바꾸기 전에 참조 쿼리나 복사본을 만들어 비교합니다.

1. 원본 행 수를 기록합니다.
2. 중복 판단에 사용할 열을 고릅니다.
3. 원시 키의 고유값과 개수를 확인합니다.
4. 업무 규칙에 필요할 때만 공백 제거와 대문자 변환을 적용합니다.
5. 정규화 전후의 후보 행을 비교합니다.
6. 어떤 행을 남겨야 하는지 별도 기준을 정합니다.
7. 중복 제거 후 행 수와 합계를 다시 확인합니다.

`Text.Trim`은 기본적으로 텍스트 앞뒤 공백을 제거합니다. `Text.Upper`는 텍스트를 대문자로 바꾸며 필요하면 culture를 지정할 수 있습니다. 예를 들어 영문 코드에 다음과 같은 정규화 열을 만들 수 있습니다.

```powerquery
Text.Upper(Text.Trim([key]), "en-US")
```

이 규칙이 모든 데이터에 맞는 것은 아닙니다. 공백 자체가 유효한 값이거나 대소문자를 구분하는 코드라면 원본을 그대로 비교해야 합니다. 정규화한 키는 원본 열을 덮어쓰기보다 별도 열로 남겨 차이를 확인하는 편이 안전합니다.

## “첫 행을 남긴다”는 가정은 피합니다

Microsoft 문서는 중복 제거에서 어떤 중복 행이 유지될지 보장되지 않는다고 설명합니다. 현재 화면의 첫 행이 항상 남는다고 가정해서는 안 됩니다.

예를 들어 같은 고객 코드에 아래 두 행이 있을 수 있습니다.

```text
A001 | 2026-09-01 | 검토 중
A001 | 2026-09-15 | 완료
```

단순히 `A001` 열만 선택해 중복을 제거하면 어떤 상태 행이 남아야 하는지 업무 규칙이 표현되지 않습니다. 최신 날짜, 승인 상태, 우선순위처럼 남길 행을 결정하는 조건이 있다면 그 조건을 먼저 명시하고 결과를 별도로 검증해야 합니다.

## 실제 재현 결과

2026년 9월 13일 Windows의 Excel 16.0 빌드 20326, `ko-KR` 환경에서 고정된 합성 입력으로 재현했습니다.

원시 키를 그대로 비교한 결과는 다음 네 범주였습니다.

```text
빈 값
" A "
"A"
"a"
```

앞뒤 공백을 `Text.Trim`으로 제거하고 `en-US` 기준 `Text.Upper`를 적용한 뒤에는 다음 두 범주가 남았습니다.

```text
빈 값
"A"
```

| 비교 방식 | 고유 키 수 | 확인된 키 |
|---|---:|---|
| 원시 텍스트 | 4 | 빈 값, `" A "`, `"A"`, `"a"` |
| Trim + Upper | 2 | 빈 값, `"A"` |

두 결과 모두 자료형과 허용 가능한 원본 행 범위를 확인했습니다. 이 실행에서 특정 행이 남았다는 사실을 일반 규칙으로 사용하지 않았습니다.

별도의 완전 중복 시험에서는 바이트 단위로 같은 전체 행 한 쌍을 모든 열 기준으로 비교해 한 행으로 줄어드는 것을 확인했습니다. 같은 입력을 특정 키 열만으로 비교한 변형에서는 유효한 생존 행인지 확인했지만, 어느 행이 반드시 남아야 한다고 주장하지 않았습니다.

## 빈 값은 자동으로 버리지 않습니다

빈 키가 중복되어도 무조건 삭제할 수 있는 것은 아닙니다. “아직 코드가 배정되지 않은 서로 다른 주문”일 수 있기 때문입니다.

- 빈 키를 허용하지 않는다면 중복 제거 전에 오류나 보류 대상으로 분리합니다.
- 빈 키가 정상이라면 다른 열을 함께 비교해 같은 행인지 판단합니다.
- 빈 문자열과 null을 같은 범주로 볼지 업무 규칙에 명시합니다.

중복 제거는 데이터 품질 문제를 숨기는 수단이 아닙니다. 빈 키나 충돌 키가 왜 생겼는지 확인할 수 있도록 제거 전 후보 수를 기록해야 합니다.

## 결과 검증 체크리스트

- [ ] 공백과 대소문자를 같은 값으로 볼지 정했습니다.
- [ ] 원본 키와 정규화 키를 함께 비교했습니다.
- [ ] 빈 문자열과 null 처리 규칙을 정했습니다.
- [ ] 특정 중복 행이 우연히 남는 결과에 의존하지 않습니다.
- [ ] 제거 전후의 행 수와 주요 합계를 확인했습니다.
