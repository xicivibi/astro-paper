`02/03/2026`은 어떤 환경에서는 2월 3일, 다른 환경에서는 3월 2일로 해석될 수 있습니다. CSV에 날짜 형식 정보가 따로 없으면 파일을 만든 지역과 파일을 여는 환경의 규칙이 다를 때 문제가 생깁니다.

Power Query에서는 날짜 열을 변환할 때 **Using Locale**을 선택해 자료형과 로캘을 함께 지정할 수 있습니다. Microsoft Support는 로캘 충돌 시 **Change Type 설정, Power Query 설정, 운영체제 설정** 순서로 적용된다고 설명합니다.

## 먼저 원본 형식을 확인합니다

가져오기 전에 날짜 값의 실제 규칙을 파일 제공자에게 확인합니다.

- `dd/MM/yyyy`: 일/월/년
- `MM/dd/yyyy`: 월/일/년
- `yyyy-MM-dd`: 연/월/일

값 몇 개만 보고 형식을 추측하면 안 됩니다. `13/03/2026`은 일/월/년이라는 단서를 주지만 `02/03/2026`은 두 방식으로 모두 유효합니다. 날짜 형식을 알 수 없다면 변환을 보류하고 원본 열을 텍스트로 유지합니다.

## CSV를 Power Query로 가져옵니다

1. Excel에서 **데이터 > 텍스트/CSV에서**를 선택합니다.
2. 파일을 선택하고 미리보기에서 구분자와 파일 원본을 확인합니다.
3. 바로 로드하지 않고 **데이터 변환**을 선택합니다.
4. 날짜 열의 자동 변환 단계가 생겼다면 결과를 먼저 확인합니다.
5. 원본 값과 비교할 수 있도록 날짜 열을 복제하거나 원본 쿼리를 보존합니다.

Power Query는 CSV 같은 비정형 원본의 값을 검사해 자료형을 자동 감지할 수 있습니다. 자동 감지 결과가 실제 업무 규칙과 다르면 해당 단계를 수정해야 합니다.

## Using Locale로 날짜를 변환합니다

Power Query 편집기에서 다음 순서로 설정합니다.

1. 날짜로 바꿀 텍스트 열을 선택합니다.
2. 열 머리글을 마우스 오른쪽 버튼으로 누릅니다.
3. `형식 변경 > 로캘 사용(Using Locale)`을 선택합니다.
4. 자료형으로 `날짜(Date)`를 선택합니다.
5. 원본 날짜 형식에 맞는 로캘을 선택합니다.
6. 변환된 날짜와 오류 행을 확인합니다.

예를 들어 원본이 `dd/MM/yyyy` 규칙이라면 그 형식을 사용하는 로캘을 선택하고, `MM/dd/yyyy` 규칙이라면 해당 규칙을 사용하는 로캘을 선택합니다. 로캘 이름만 보고 결정하지 말고 제공자가 명시한 파일 형식과 함께 확인해야 합니다.

## CSV 원본 로캘과 열 변환 로캘을 구분합니다

Microsoft Support는 Power Query에서 다음 세 위치의 로캘을 설명합니다.

1. 운영체제의 지역 설정
2. Power Query 또는 통합 문서의 기본 지역 설정
3. 특정 열의 Change Type에 지정한 로캘

CSV의 **파일 원본 로캘**은 가져오기 단계의 해석에 영향을 줄 수 있고, 열의 **Using Locale**은 선택한 열을 특정 자료형으로 변환할 때 적용됩니다. 두 설정은 목적이 다르므로 같은 것으로 취급하지 않습니다.

여러 사람이 같은 통합 문서를 사용한다면 열 변환 단계에 로캘을 명시하고, 원본 파일의 날짜 규칙도 운영 문서에 기록합니다. 통합 문서 작성자가 저장한 Power Query 로캘은 다른 사용자에게 전달될 때 유지된다고 Microsoft가 안내합니다.

## 오류 행은 삭제하지 말고 분리합니다

`31/02/2026`처럼 존재하지 않는 날짜, 빈 값, 형식이 섞인 값은 변환 오류가 될 수 있습니다. 오류가 발생했다는 이유로 행을 바로 삭제하면 원본 데이터의 문제를 숨길 수 있습니다.

- 오류 행 수를 기록합니다.
- 원본 날짜 문자열을 함께 보존합니다.
- 잘못된 날짜와 형식이 다른 날짜를 구분합니다.
- 제공자에게 수정된 원본을 요청할 수 있도록 행 식별자를 남깁니다.
- 오류를 null로 바꾼다면 그 규칙과 영향을 문서화합니다.

정상 행만 필요한 보고서와 데이터 품질 확인용 오류 목록을 별도 쿼리로 나누면 원본을 잃지 않고 운영할 수 있습니다.

## 결과 검증 방법

변환 후에는 모호하지 않은 경계값과 모호한 값을 함께 확인합니다.

| 원본 예시 | 확인할 점 |
|---|---|
| `02/03/2026` | 2월 3일과 3월 2일 중 의도한 날짜인지 |
| `13/03/2026` | 일/월/년 규칙에서 정상 변환되는지 |
| `2026-03-13` | ISO 형태를 같은 열에서 허용하는지 |
| `31/02/2026` | 오류로 분리되는지 |

날짜 표시 형식만 바뀌었는지, 실제 날짜 값이 바뀌었는지도 구분합니다. 셀의 화면 표시가 같아 보여도 내부 값이나 변환 단계가 다를 수 있습니다.

## 이 글의 확인 범위

이 글은 Microsoft Support가 공개한 Excel용 Power Query의 `Using Locale`, CSV 로캘, 통합 문서 지역 설정, 자료형 변경 절차를 기준으로 작성했습니다. 해당 문서의 제품 적용 범위는 Excel for Microsoft 365, Excel 2024, Excel 2021입니다.

이 글에서는 특정 로캘 조합의 정확한 변환 결과를 직접 실행한 것으로 주장하지 않습니다. Excel 빌드, 운영체제, 실제 입력 파일에 따른 결과는 작업 환경에서 원본과 대조해야 합니다. 별도의 M 함수 `Date.FromText`에 명시적 `Format`을 전달하는 동작도 이 글의 확인 범위에 포함하지 않았습니다.

- [ ] 원본 날짜 열을 텍스트로 보존했습니다.

- [ ] 오류 행을 삭제하기 전에 별도로 기록했습니다.
