`00123`은 수량 123이 아니라 상품 코드일 수 있습니다. `12345678901234567`도 계산할 숫자가 아니라 주문 식별자일 수 있습니다. 이런 값을 Excel이 숫자로 바꾸면 앞자리 0이 사라지거나 긴 값이 의도와 다르게 표시·저장될 수 있습니다.

Microsoft는 Excel이 숫자 모양의 텍스트에서 앞자리 0을 제거하고, 큰 숫자를 과학적 표기법으로 바꿀 수 있다고 안내합니다. 특히 숫자는 15자리 정밀도 제한이 있으므로 16자리 이상의 코드는 텍스트로 다뤄야 합니다.

핵심은 **파일을 연 뒤 서식을 바꾸는 것이 아니라, 가져오는 단계에서 식별자 열의 형식을 텍스트로 지정하는 것**입니다.

## 먼저 원본을 복사합니다

작업 전에 CSV 원본을 복사합니다. 이미 숫자로 변환된 셀에 사용자 지정 서식을 적용해도 사라진 앞자리 0이나 15자리 뒤의 원래 값을 복원할 수는 없습니다. Microsoft 공식 문서도 사후 서식 변경은 이미 제거된 앞자리 0을 되살리지 않는다고 설명합니다.

식별자 열에는 다음과 같은 값이 포함될 수 있습니다.

```text
product_code,external_id
00123,12345678901234567
00007,98765432109876543
```

이 값들에 합계·평균 같은 계산을 할 필요가 없다면 숫자보다 텍스트 형식이 맞습니다.

## Power Query에서 텍스트로 지정해 가져오는 순서

Microsoft가 안내하는 기본 경로는 다음과 같습니다. Excel 버전이나 운영체제에 따라 메뉴 표현은 조금 다를 수 있습니다.

1. 빈 통합 문서에서 **데이터 → 텍스트/CSV에서**를 선택합니다.
2. 파일을 선택하고 미리보기에서 **데이터 변환** 또는 **편집**을 누릅니다.
3. Power Query 편집기에서 상품 코드와 외부 ID 열을 선택합니다.
4. **홈 → 변환 → 데이터 형식 → 텍스트**를 선택합니다.
5. 열 머리글의 형식 표시가 텍스트인지 확인합니다.
6. **닫기 및 로드**를 선택합니다.
7. 로드된 결과를 원본 복사본과 문자 단위로 대조합니다.

여러 열을 함께 바꿀 때는 `Ctrl`을 누른 채 열 머리글을 선택할 수 있습니다. 자동으로 추가된 **변경된 유형** 단계가 먼저 숫자 변환을 했다면, 그 단계의 위치와 내용을 확인하고 식별자 열이 텍스트로 처리되게 수정해야 합니다.

## 표시만 맞는지, 값 자체가 보존됐는지 구분합니다

셀에 `00000` 같은 사용자 지정 표시 형식을 적용하면 숫자 123을 화면에서 `00123`처럼 보이게 할 수 있습니다. 이것은 값 123에 표시 규칙을 얹은 것입니다. 다른 시스템으로 다시 내보내거나 조인 키로 쓸 식별자를 보존하는 목적과는 다릅니다.

다음 세 항목을 각각 확인하세요.

| 확인 항목 | 기대 결과 |
|---|---|
| 표시값 | `00123`과 17자리 ID 전체가 보임 |
| Power Query 열 형식 | 텍스트 |
| 원본 대조 | 앞자리 0과 모든 자릿수가 일치 |

셀 너비가 좁아 과학적 표기법으로 보이는 경우와 실제 값이 변환된 경우도 구분해야 합니다. 열을 넓히는 것만으로 해결됐다고 판단하지 말고 수식 입력줄과 원본을 함께 봅니다.

## 공백이 있는 식별자는 임의로 지우지 않습니다

CSV 값이 다음처럼 큰따옴표 안에 공백을 포함할 수 있습니다.

```csv
kind,product_code,external_id
quoted,00123,12345678901234567
spaced," 00123 "," 12345678901234567 "
```

공백이 단순 오염인지, 고정 폭 코드의 일부인지 먼저 결정해야 합니다. Power Query에는 텍스트 열의 앞뒤 공백을 제거하는 **Trim** 명령이 있지만, 의미 있는 공백까지 없앨 수 있습니다.

공백 제거가 업무 규칙으로 확정된 경우에만 다음처럼 별도 단계로 적용합니다.

1. 원본 열을 그대로 보존하거나 쿼리를 복제합니다.
2. 대상 텍스트 열을 선택합니다.
3. **변환 → 형식 → 공백 제거(Trim)**를 적용합니다.
4. 원본 값과 정규화한 값을 각각 대조합니다.

Microsoft 문서는 Power Query의 텍스트 명령에 Trim과 대문자 변환 등이 포함된다고 안내합니다. 원본 열을 바꾸는 **변환** 탭과 새 열을 만드는 **열 추가** 탭의 차이도 확인해야 합니다.

## 실제 재현 결과

2026년 9월 13일에 Windows의 Excel 16.0 빌드 20326, `ko-KR` 환경에서 합성 CSV를 Power Query로 가져와 확인했습니다.

- `00123`, `00007`을 텍스트로 지정했을 때 앞자리 0이 유지됐습니다.
- `12345678901234567`, `98765432109876543`을 텍스트로 지정했을 때 17자리가 그대로 유지됐습니다.
- 큰따옴표 필드의 앞뒤 공백을 유지한 원본 결과와, 별도의 Trim 단계를 적용한 결과가 각각 사전 정의한 기대값과 일치했습니다.
- 확인 대상 열의 형식이 모두 텍스트로 기록됐습니다.

이 결과는 해당 Excel 빌드와 합성 입력에 대한 재현 기록입니다. 다른 Excel 버전, Mac, 실제 업무 파일의 모든 조합을 보장하지 않습니다. 문서의 **자동 데이터 변환 설정** 기능은 Microsoft 365와 Excel 2024 계열에 한정해 안내되므로, 이전 버전에서는 Power Query의 텍스트 형식 지정 절차를 우선 확인하세요.

## 새로고침까지 확인해야 끝납니다

Power Query를 쓰는 이유는 같은 변환을 다시 적용할 수 있기 때문입니다. 첫 로드 뒤 파일을 갱신하거나 같은 구조의 새 파일로 바꿀 때도 식별자 열이 텍스트로 유지되는지 확인합니다.

1. 쿼리의 **적용된 단계**에 텍스트 형식 지정이 남아 있는지 봅니다.
2. **데이터 → 모두 새로 고침**을 실행합니다.
3. 앞자리 0, 긴 ID, 빈 값, 공백 포함 값의 대표 행을 다시 대조합니다.
4. 열 이름이나 파일 구조가 바뀌어 오류가 생기지 않았는지 확인합니다.

## 저장 전 체크리스트

- [ ] 원본 CSV 복사본을 보존했습니다.
- [ ] 코드·계정·우편번호처럼 계산하지 않을 열을 구분했습니다.
- [ ] 가져오기 단계에서 해당 열을 텍스트로 지정했습니다.
- [ ] `00123`, `00007`의 앞자리 0이 유지됩니다.
- [ ] 16자리 이상 ID의 모든 자릿수가 원본과 같습니다.
- [ ] 공백 제거는 업무 규칙이 확정된 열에만 적용했습니다.
- [ ] 로드 후와 새로고침 후 결과를 모두 대조했습니다.

CSV의 구분자나 문자 인코딩부터 확실하지 않다면 먼저 [CSV 한글 깨짐·열 밀림 진단](/posts/csv-korean-encoding-delimiter-checklist/)을 확인하고, [브라우저 내 CSV 점검 도구](/tools/csv-preview/)에서 원본 구조를 미리 살펴보세요.
